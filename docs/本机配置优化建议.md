# 当前电脑 Clash Verge Rev 配置优化建议

检查日期：2026-09-13

> 本文记录建议和只读/临时隔离测试结果。此次检查没有部署、重载或修改 TUN、MTU、DNS、系统代理及 EasyConnect；本机仅保留此前加入的 Elsevier PDF/CDN 直连规则。

## 当前结论

当前配置整体稳定，建议继续作为基础配置使用，不要直接用项目中的公共模板整体替换。

当前主要状态：

- Clash Verge Rev 2.5.2，Mihomo 1.19.29。
- TUN 已开启，使用 `mixed` 栈。
- TUN 和 WLAN MTU 均为 1500，与当前 WSL mirrored 默认出口匹配。
- 系统代理关闭，混合端口为 7897。
- Fake-IP DNS、DNS 劫持和局域网路由排除已经生效。
- OpenAI、ChatGPT、API、静态资源和 WebSocket 核心域名已经走 `🔰 选择节点`。
- 三轮公开端点测试均收到服务器响应，没有连接超时。
- 近期日志没有 OpenAI、ChatGPT、TLS、WebSocket 或 timeout 错误。
- 2026-09-13 临时隔离生成通过 Mihomo 校验，测试前后 4 个本机运行配置文件哈希一致。
- OpenAI、Gemini、Microsoft、ScienceDirect、Elsevier、IEEE Xplore 和 Scopus 公共端点均完成了 TLS/HTTP 连接。

## 建议保留

- 保留当前 TUN、`mixed` 栈和 MTU 1500。
- 保留当前 DNS 设置和订阅自带的大型规则集。
- 保留当前局域网 `route-exclude-address`，避免本地开发服务绕远。
- 保留系统代理关闭状态，由 TUN 统一接管流量。
- OpenAI 核心、登录、静态资源和 WebSocket 应始终使用同一个稳定策略组。
- ScienceDirect PDF、`sciencedirectassets.com` 和 `els-cdn.com` 当前已优先命中 `DIRECT`；无需继续追加同类规则。

## 建议修改，但暂不执行

### 1. 补齐 OpenAI/ChatGPT 辅助域名

当前核心域名覆盖良好，但以下辅助服务会落到 `🐟 漏网之鱼`。建议将它们明确放到 OpenAI 使用的同一策略组：

```yaml
- DOMAIN-SUFFIX,oaistatsig.com,🔰 选择节点
- DOMAIN-SUFFIX,workos.com,🔰 选择节点
- DOMAIN-SUFFIX,workoscdn.com,🔰 选择节点
- DOMAIN,workos.imgix.net,🔰 选择节点
- DOMAIN-SUFFIX,ct.sendgrid.net,🔰 选择节点
- DOMAIN,rum.browser-intake-datadoghq.com,🔰 选择节点
```

这样可以减少登录、企业身份认证、功能开关和前端资源使用不同出口的情况。

### 2. 建议建立独立 OpenAI 策略组

可以新增一个手动选择型策略组，例如 `🤖 OpenAI`，由用户固定选择一个可靠节点。所有 OpenAI/ChatGPT 域名统一指向该组，避免自动测速或频繁切换造成出口 IP 变化。

### 3. 暂不阻断 QUIC

当前配置虽然存在 `profile.block-quic: true`，但最终规则中没有 UDP/443 拒绝规则，因此实际上没有明确阻断 QUIC。现有连接正常，建议暂时保持现状。

只有确认代理节点的 UDP/443 不稳定时，才考虑阻断 QUIC；不要阻断 ChatGPT Voice 可能使用的 UDP 3478。

### 4. DNS 监听后续再收紧

当前 DNS 监听为 `0.0.0.0:53`。它对现有 TUN/WSL 环境工作正常，因此无需立即修改。后续如果确认 WSL 不依赖该监听，可评估改为回环地址，降低不必要的局域网暴露。

Codex 自身的网络沙盒与 Clash 路由是两层不同机制。本地地址应采用精确规则，不应通过代理整个 Codex、浏览器或编辑器进程解决。相关原则可参考 [ChatGPT Learn 网络权限说明](https://learn.chatgpt.com/zh-Hans/docs/permissions)。

### 5. Gemini、PowerShell 与 Chrome

- Gemini 网页、登录、API 与 Code Assist 当前应统一到同一个稳定出口；可以显式使用 `-GeminiGroup`。
- PowerShell 默认依赖已经启用的 TUN；仅对不能被接管的命令行工具点源启用 Session 代理。
- Chrome 继续按域名分流，不增加 `PROCESS-NAME,chrome.exe`，也不在没有证据时全局阻断 QUIC。

### 6. Microsoft Store 与微软应用

本机只读审计结果：

- Microsoft Store 版本为 `22607.1401.9.0`。
- `InstallService`、`ClipSVC`、`AppXSvc` 和 `wuauserv` 正常运行。
- `DoSvc` 当前停止但启动类型为手动，属于按需启动状态，不建议强制常驻。
- WinHTTP 当前为直连，没有遗留永久代理。

建议将微软流量分为两类：

- 微软账号、商店目录、许可证、Office、OneDrive、Teams 和 Edge 控制链路默认 `DIRECT`，并可通过 `-MicrosoftGroup` 覆盖。
- Microsoft Store 应用包、Windows Update、Office 更新与 Delivery Optimization 下载默认使用 `DIRECT`，保留本地 CDN 速度；只有直连测试失败才改用 `-MicrosoftDownloadGroup` 指定代理组。

不建议代理整个 Microsoft Store、`svchost.exe`、`wsappx` 或 Windows Update 进程，这会连带影响系统服务、局域网 Delivery Optimization 与其他 Windows 功能。

### 7. ScienceDirect PDF 与 Chrome

本机已完成实际 A/B 验证：

- 普通 Chrome 在 Adobe Acrobat 扩展接管 PDF 时曾出现“未能加载 PDF”。
- 相同网络下，无痕窗口能够打开 PDF。
- 临时停用 Adobe Acrobat 扩展后，普通 Chrome 也能够打开同一类 PDF。
- 因此本次主要原因是 Acrobat 扩展对 ScienceDirect 短期签名 PDF 的接管，不是 EasyConnect、Clash、MTU 或 Chrome 原生 PDF 查看器。

建议继续使用 Chrome 内置 PDF 查看器，并将 Acrobat 扩展保持停用；如果以后重新启用，应关闭其默认接管在线 PDF 的功能。脚本只应检查并提示扩展状态，不应自动停用或卸载浏览器扩展。

### 8. 当前运行规则需要统一

修正规则解析器后的只读审计结果如下：

- ScienceDirect PDF 和 Elsevier CDN 三项均已正确命中 `DIRECT`。
- 7 个 OpenAI 辅助域名仍落入 `🐟 漏网之鱼` 或国内组，适合在维护窗口统一到 `🔰 选择节点`。
- 9 个 Gemini/API 域名当前命中 `🚀 Antigravity`。这并非连接故障；如果该组就是本机预期出口，生成时应显式使用 `-GeminiGroup "🚀 Antigravity"`，避免审计误认为应跟随主策略组。
- Microsoft 公共端点均能连接，但当前分别落入主代理、OneDrive 专组和漏网组。不要为了消除警告一次性改动全部微软流量，应先分别验证商店登录/许可证、OneDrive 和更新下载，再决定 `-MicrosoftGroup` 与 `-MicrosoftDownloadGroup`。
- 最终配置仍保留部分指向旧名称 `选择节点` 的规则，而真实策略组为 `🔰 选择节点`。这些陈旧规则应在未来部署项目 Merge 时清理。

当前订阅绑定的是另一份本机 Merge，而不是项目的 `profiles\Merge.yaml`，因此项目新生成的完整规则尚未整体进入最终配置。

这不会否定目前公共端点测试成功，但规则目标不一致会降低长期可维护性。建议下一次维护窗口先运行 `-Action IsolatedTest -ProxyGroup "🔰 选择节点"`，确认通过后再决定是否部署和绑定 Merge。当前本机设置按用户要求暂不变。

## 推荐实施顺序

1. 每次改模板或准备部署前，先运行临时隔离测试，不直接操作 AppData 运行配置。
2. 统一旧的 `选择节点` 与真实策略组 `🔰 选择节点`，并补齐 OpenAI/Gemini 辅助域名规则。
3. 验证 ChatGPT 登录、消息流、文件上传和 Codex 长连接。
4. 再决定是否建立独立 `🤖 OpenAI` 策略组。
5. 微软控制链路、商店和更新下载先保持 `DIRECT`；只有直连失败才测试代理组。
6. 验证 Microsoft Store 首页、登录、许可证、安装和更新。
7. Chrome 保持使用内置 PDF 查看器；Acrobat 扩展继续停用或关闭在线 PDF 接管。
8. QUIC、DNS 监听和 MTU 暂时不改。
9. 正式部署必须创建独立快照，失败时恢复到本次修改前状态。

## 验收标准

- `api.openai.com` 能完成 TLS 连接并返回 HTTP 响应。
- `chatgpt.com` 和 `ws.chatgpt.com` 能持续连接，无频繁断流。
- 登录、文件上传和静态资源能够正常加载。
- OpenAI 官方相关域名均命中同一个代理策略组。
- Gemini 网页、API 和登录链路使用同一出口。
- Microsoft Store 可以加载目录、登录账号、获取许可证并安装/更新应用。
- Windows Update 与 Delivery Optimization 不因代理规则出现错误或重复下载。
- Clash Verge 和 Mihomo 日志中没有相关 timeout、TLS 或 WebSocket 错误。
